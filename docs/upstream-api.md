# FastClaw Upstream App Integration API

This is the integration contract for applications that use FastClaw as their
agent runtime.

FastClaw is split into two layers:

- **The agent runtime** (this API) stores agent configuration, runs the agent
  loop, sandbox and tools, stores sessions and memory, and meters usage.
- **Your app** owns everything about its users: sign-in, which user may use
  which agent, chat records, billing rules, IM channels, and session IDs.

Data flows one way: your app calls the runtime; the runtime never calls your
app back and never knows who your users are. FastClaw's own console and IM
channels are apps in the same sense — they serve users who registered with
FastClaw directly.

## Which Interface To Use

| Need | Interface | Notes |
|---|---|---|
| Create and manage your app's agents | `/v1/agents` | Create, list, read, update, delete; write identity files. |
| Chat with an agent | `POST /v1/chat/completions` | OpenAI-compatible, plus FastClaw extensions. |
| Query usage / token spend | `GET /v1/usage` | By agent and by end-user, for your billing. |
| Set per-user limits | `/v1/quota` | For subscription and entitlement enforcement. |
| Provision an end-user up front | `POST /v1/users` | Optional; chat provisions lazily. |
| Admin/dashboard automation | `/api/*` or `fastclaw ...` CLI | Serves the FastClaw console. No stability promise for integrators. |
| Coding-agent live preview runtime | `docs/coding-agent-runtime.md` | Documented separately. |

Integrations should depend on `/v1/*` only.

## Accounts, Keys And Agents

| Object | Meaning |
|---|---|
| Account | The tenant: the FastClaw account your integration runs under. Use one account per integration environment that must be isolated, e.g. `douchat-prod`, `douchat-dev`. |
| API key | Belongs to the account. May have several (rotation, revocation). A `user` key operates on every agent of the account; an `agent` key only on the agents granted to it. |
| Agent | Belongs to the account. Created in the console or through `POST /v1/agents`. The runtime does not record which of your users an agent "belongs to" — keep that in your app (optionally mirrored into `metadata`). |
| `session_key` | One conversation's history. Generated by your app. |
| `end_user` | Optional data namespace: your user's ID. Decides where personal data lives; never decides which agents can be used. |

**Your app must check "may this user use this agent?" before every call.** The
runtime only guarantees isolation between accounts: account A's keys can never
see or use account B's agents.

**Which key?** An integration that talks to fixed agents (e.g. one image
editing agent) needs an `agent` key granted just those agents. An integration
that creates its own agents through the API needs a `user` key — give it its
own account, so its keys can't reach agents you use elsewhere.

### Where data lives

| Data | Keyed by |
|---|---|
| Agent persona, skills, tool config (SOUL.md, IDENTITY.md, …) | account + agent |
| Session history | account + agent + `session_key` (+ `end_user` when given) |
| Personal profile and memory (USER.md, MEMORY.md) | account + agent + `end_user` — created only when `end_user` is given |
| The agent's own memory when no `end_user` is given | account + agent, shared by every such call |
| Usage | account + agent + `end_user` + day |

### Typical calls

| Scenario | `session_key` | `end_user` |
|---|---|---|
| A user chats with their own agent (Douchat DM) | `douchat:<conversation id>:<topic id>` | not set |
| Several people talk to one agent in a group | `douchat:<group id>:<topic id>` | not set; the speaker goes in `params.speaker` |
| Many people each privately chat with one public agent (weclaw, support bot) | `weclaw:<user id>:<agent id>` | the user's ID |

## Authentication

Every request carries an API key of your account:

```http
Authorization: Bearer fcak_...
```

| Key type | Use |
|---|---|
| `user` | Can manage and use every agent of the account, including ones created later. |
| `agent` | Scoped to explicit agent IDs; cannot create or delete agents. A request that names no agent uses the key's only agent. |
| `admin` | Platform automation. On `/v1` it is still limited to its own account's agents. |

Never expose a FastClaw API key to browsers or mobile apps.

`X-Fastclaw-End-User` (or the chat body field `user`) names the end-user. It
selects the data namespace only; agents are always resolved from the account.

## Agents

### `POST /v1/agents`

Creates an agent owned by the account.

```http
POST /v1/agents
Authorization: Bearer fcak_...
Content-Type: application/json

{
  "name": "周报助手",
  "description": "每周五汇总团队进展",
  "instructions": "你是……（写入 SOUL.md）",
  "model": "anthropic/claude-sonnet-5-5",
  "metadata": { "app_user": "douchat-user-123" }
}
```

```json
{
  "agent": {
    "id": "agt_2834a7a1e660d509b83d",
    "display_name": "周报助手",
    "name": "agt_2834a7a1e660d509b83d",
    "description": "每周五汇总团队进展",
    "model": "anthropic/claude-sonnet-5-5",
    "metadata": { "app_user": "douchat-user-123" },
    "created_at": "2026-10-04T08:00:00Z",
    "updated_at": "2026-10-04T08:00:00Z"
  }
}
```

- Only `name` is required. `instructions` is written to SOUL.md. `model` is
  `<provider>/<model>`; omit it to use the account's default model.
- `metadata` is your own string key/value data. The runtime stores it and
  filters by it, and never uses it for authorization. Limits: at most 16 keys,
  keys ≤ 64 characters, values ≤ 512 characters.
- `display_name` is the human name. `name` equals `id` and is kept only for
  compatibility with older clients; don't display it.

Every agent endpoint returns the same agent object.

### `GET /v1/agents`

Lists the account's agents the key may use, newest first, straight from the database.

| Param | Notes |
|---|---|
| `limit` | Page size, 1–100. Omit to get every agent in one response. |
| `cursor` | `next_cursor` from the previous page. |
| `metadata[key]=value` | Only agents whose metadata matches; also accepted as `metadata.key=value`. Several filters are ANDed. |

```json
{
  "agents": [ { "id": "agt_...", "display_name": "周报助手", "...": "..." } ],
  "has_more": true,
  "next_cursor": "agt_..."
}
```

### `GET /v1/agents/{id}`

Reads one agent.

### `PATCH /v1/agents/{id}`

Updates `name`, `description`, `instructions` (SOUL.md), `model` and
`metadata`. Omitted fields are unchanged. `model: ""` clears the override.
`metadata` is merged: a key set to `null` or `""` is removed.

### `PUT /v1/agents/{id}/system-files/{name}`

Writes one identity file: `SOUL.md`, `IDENTITY.md`, `AGENTS.md`,
`BOOTSTRAP.md`, `TOOLS.md`, `HEARTBEAT.md` or `KNOWLEDGE.md` (max 256KB).
These are shared by every end-user of the agent.

```json
{ "content": "# Identity\n..." }
```

### `DELETE /v1/agents/{id}`

Deletes the agent. A second delete returns `404 agent_not_found`; treat that
as "already deleted".

## Chat API

### `POST /v1/chat/completions`

OpenAI-compatible endpoint with FastClaw extensions.

```http
POST /v1/chat/completions
Authorization: Bearer fcak_...
Content-Type: application/json
X-Fastclaw-Session-Key: douchat:group_123:topic_9

{
  "agent_id": "agt_2834a7a1e660d509b83d",
  "stream": true,
  "messages": [{ "role": "user", "content": "帮我总结下今天的讨论" }],
  "params": { "speaker": { "id": "douchat-user-456", "name": "Bob" } }
}
```

**Agent selection is strict.** Set `agent_id` (body) or `X-Fastclaw-Agent-ID`
(header; the body wins). If that agent doesn't exist or isn't one of your
agents the key may use, the response is `404` with code `agent_not_found` and no agent
answers. Only when no agent is named does FastClaw use a default: an `agent`
key's only agent, or the account's only agent.

**Session.** `X-Fastclaw-Session-Key` selects the conversation history. If
omitted, every call starts a new session — always send it.

**End-user.** `user` (body) or `X-Fastclaw-End-User` (header; the body wins)
names your user. The agent is still your app's agent; the end-user only
decides where session history, USER.md and personal memory are stored, so
different end-users of one agent never see each other's data. Without an
end-user, all calls share the agent's own memory.

**Speaker.** In group conversations put the current speaker in
`params.speaker` as `{"id": "...", "name": "..."}`. The agent sees it as
context for this turn only. It is not persisted and grants nothing.

FastClaw extensions:

| Field | Type | Purpose |
|---|---|---|
| `agent_id` | string | Agent to call. Body wins over header. |
| `user` | string | End-user ID. Body wins over `X-Fastclaw-End-User`. |
| `params` | object | Per-turn structured context shown to the agent. Not persisted. `params.speaker` is the group-chat speaker. |
| `project_id` | string | Optional. Files the conversation under one of the agent's projects so it shares that project's workspace. `404 project_not_found` if it doesn't exist in this namespace. |
| `images` | string[] | Image URLs/data URLs shown to vision models and materialized into workspace. |
| `imageUrls` | string[] | Alias for `images`. |
| `attachments` | array | General files materialized into workspace (`{"url", "name"}`). Use for PDFs, docs, zips, etc. |

Streaming responses follow the OpenAI SSE shape:

```text
data: {"id":"chatcmpl-...","object":"chat.completion.chunk","choices":[{"delta":{"content":"..."},"index":0}]}

data: [DONE]
```

Non-streaming responses follow the OpenAI response shape (`choices[0].message`).

### Session key guidance

Generate session keys from your own conversation model, prefixed with your app:

```text
<app>:<conversation>[:<topic>]
```

Don't reuse a session key for unrelated conversations. Session keys control
chat history and usage grouping.

## Usage And Quotas

### `GET /v1/usage`

| Param | Notes |
|---|---|
| `days` | Lookback window, default `30`, max `90`. |
| `agent_id` | Only this agent's usage. |
| `end_user` | Only this end-user's usage (the ID you send as `user` / `X-Fastclaw-End-User`). Unknown end-users return zero usage. |
| `scope=app` | The whole account: its own calls plus every end-user's. |
| `user_id` | Legacy: a FastClaw user ID; must be the account or one of its end-users. |

Without `end_user`, `scope` or `user_id`, the result covers the caller's own
namespace (the account, or the end-user named by `X-Fastclaw-End-User`).

```http
GET /v1/usage?scope=app&days=7
Authorization: Bearer fcak_...
```

```json
{
  "userId": "u_app",
  "scope": "app",
  "days": 7,
  "daily": [
    {
      "day": "2026-10-04",
      "agentId": "agt_...",
      "userId": "u_...",
      "endUser": "douchat-user-123",
      "model": "claude-sonnet-5-5",
      "inputTokens": 100,
      "outputTokens": 50,
      "cacheReadTokens": 0,
      "cacheCreationTokens": 0,
      "requestCount": 1
    }
  ],
  "totals": {
    "inputTokens": 100,
    "outputTokens": 50,
    "cacheReadTokens": 0,
    "cacheCreationTokens": 0,
    "requestCount": 1
  }
}
```

`endUser` is empty for calls made without an end-user. Roll the rows up by
`endUser` and `agentId` to bill your own users.

### `PUT /v1/quota`, `GET /v1/quota`, `DELETE /v1/quota`

Set, read and remove monthly limits for the account or one of its end-users
(`user_id` is the FastClaw user ID returned by `POST /v1/users`). Other users'
IDs are rejected with `403 forbidden`.

```json
{
  "user_id": "u_...",
  "monthly_token_limit": 5000000,
  "monthly_request_limit": 10000,
  "reset_day": 1
}
```

Limits of `0` mean no limit for that dimension. `reset_day` must be `1..28`;
invalid values are normalized to `1`.

### `POST /v1/users`

Optional. Mints (or returns) the FastClaw user for one of your end-users so
you can store its `user_id` for quota calls. Chat provisions the same user
lazily the first time an end-user is named.

```json
{ "external_id": "douchat-user-123" }
```

## Errors

Every `/v1` error has the same shape:

```json
{
  "error": {
    "type": "not_found_error",
    "code": "agent_not_found",
    "message": "agent not found"
  }
}
```

Branch on `code`; it is stable. `message` is for humans and may change.

| Status | `code` | Meaning |
|---|---|---|
| `400` | `invalid_request` | Bad body, missing messages, metadata over limits, bad cursor, … |
| `401` | `unauthorized` | Missing or invalid API key. |
| `403` | `forbidden` | The key may not do this (e.g. `agent` key creating agents, foreign `user_id`). |
| `403` | `agent_quota_exceeded` | The account reached its agent quota. |
| `404` | `agent_not_found` | No such agent for this key (including other accounts' agents and agents not granted to an `agent` key). |
| `404` | `project_not_found` | `project_id` doesn't exist for this agent and namespace. |
| `404` | `quota_not_found` | No quota configured for that user. |
| `429` | `rate_limited` | Rate limit exceeded. |
| `503` | `not_configured` | Usage/quota/agent store not configured on this deployment. |

## Recommended Flow

1. Create an account for your app environment and a `user` API key; store the
   key server-side.
2. When your user creates an agent, call `POST /v1/agents` and record the
   returned `id` against your user (and in `metadata` if you want to filter).
3. Before every chat, check in your app that the user may use that agent.
4. Call `POST /v1/chat/completions` with `agent_id`, a deterministic
   `X-Fastclaw-Session-Key`, and — for per-user private data — `user`.
5. For billing, read `GET /v1/usage?scope=app` and roll up by `endUser`.

## What To Give An Agent

When asking an AI coding agent to integrate an app with FastClaw, give it:

1. This document.
2. The FastClaw base URL.
3. The API key type.
4. Your user ID field and your conversation/session ID field.
5. Whether you need usage/quota billing integration.

If the agent supports Skills, install or load
`skills/fastclaw-api-integration/SKILL.md`, the short operational version of
this contract.
